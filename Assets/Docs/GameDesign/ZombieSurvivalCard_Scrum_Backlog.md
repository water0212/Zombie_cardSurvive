# 殭屍生存卡牌 - Scrum 開發待辦清單

版本：0.3  
日期：2026-07-30  
用途：整理目前已完成、部分完成、尚未完成的開發任務，並依照 Scrum / Backlog 的方式安排優先順序。

這份文件是「開發管理文件」，不是 GDD 的替代品。  
GDD 負責描述遊戲規則與設計意圖；本文件負責描述「接下來要做什麼、先做什麼、怎樣算完成」。

## 產品目標

開發一個可遊玩的垂直切片版本，玩家可以：

1. 透過正規卡組進行回合與輪次循環。
2. 使用卡牌獲得或消耗食物、資源、能量、戰鬥值，之後加入士氣。
3. 在每輪之間處理事件選擇。
4. 使用卡牌倉庫、預設卡與替換系統調整卡組。
5. 面對由殭屍卡產生的殭屍威脅。
6. 在食物、士氣、戰鬥、探索與卡組規劃之間做出生存取捨。

## 優先級說明

- P0：核心循環必須完成，否則遊戲不能穩定測試。
- P1：遊戲主要特色與策略深度所需。
- P2：重要內容、進度系統或中後期功能。
- P3：美術、手感、音效、平衡工具與製作品質。

## 狀態說明

- 已完成：已實作，並且目前可用。
- 部分完成：已有原型，但規則、UI 或整合還不完整。
- 待辦：尚未實作。
- 阻塞：需要先決設計或其他系統完成。

## 完成定義

一個任務要被視為完成，必須符合：

- Unity Play Mode 可以正常運作，沒有 Console 編譯錯誤。
- 必要的 Inspector 欄位與 UI 綁定方式清楚。
- 功能走目前的正式資料流，不依賴一次性的測試捷徑。
- 不破壞既有的打牌、事件、替換、查看牌堆流程。
- 有清楚的手動測試方式。

### PB-P0-004 - 食物經濟 V1

狀態：已完成，已通過 Play Mode 測試  
優先級：P0  
分類：生存經濟  
目標：讓食物成為第一個真正有壓力的生存資源。

規則：
- 食物可由卡牌與事件獲得
- 食物在輪末消耗，不是每回合消耗
- Demo 階段先使用單一固定消耗值
- 食物不足時，先觸發士氣下降
- 食物上限在輪末消耗後才檢查
- 超過倉庫上限的食物會被移除
- UI 顯示：目前食物 - 每輪消耗 / 倉庫上限

驗收：
- 輪末食物會被扣除
- 食物不足時觸發士氣下降接口
- 食物超過上限時會在輪末消耗後被移除
- UI 可清楚顯示食物壓力

### PB-P0-009 - 有限地區資料規格與首批數值

狀態：待辦，設計可開始  
優先級：P0  
分類：探索 / 遊戲設計  
設計依據：GDD 第 29.2 至 29.5 節  
目標：為有限地區 Runtime 準備可測試、可比較的首批地區數值，不讓程式完成後仍缺少內容。

使用者故事：
- 身為遊戲設計者，我希望每個地區都有有限卡包、有限殭屍與熱度參數，讓探索的收益、枯竭與風險可以被實際測試。

待做：
- 為超市、住宅區、加油站、學校建立第一版地區數值表。
- 每個地區填入卡包種類、初始數量、基礎權重、殭屍初始數量、基礎遭遇率、熱度增加量與每日衰減量。
- 定義「充足 / 普通 / 稀少 / 枯竭」與「低 / 中 / 高 / 極高」的顯示門檻。
- 倉庫與軍事基地保留至有限地區流程驗證完成後再加入正式內容。

驗收：
- 四個 Demo 地區沒有缺少必要欄位。
- 普通卡包耗盡時，稀有卡包相對機率確實上升。
- 任一地區都能在有限次探索後枯竭，不存在自然補充來源。
- 數值表不包含專門清理、動態殭屍體質或完整屍群公式。

解除阻塞條件：

## 目前最推薦的下一步

目前正規牌組、輪末生存經濟、殭屍威脅、探索卡包、建築施工與製作流程都已通過目前階段的 Play Mode 驗證。下一個最推薦的開發方向是 Sprint 7：有限地區探索 Demo。

立即順序：

1. PB-P0-009：先填完四個 Demo 地區的有限存量與熱度數值。
2. PB-P0-010：建立不修改 Asset 的 `RegionRuntime`。
3. PB-P0-011：完成剩餘比例權重、扣除存量與枯竭候選過濾。
4. PB-P0-012：完成有限殭屍與探索熱度。
5. PB-P0-013：接回地區卡 UI 並完成整合 Playtest。

選擇此順序的原因：

- 它直接建立在目前已正常運作的探索與卡包流程上，修改範圍集中。
- 它能讓探索從「無限隨機獎勵」變成真正的單局有限資源決策。
- 它不需要先解決尚未定稿的基地血量、殭屍傷害與失敗條件。
- 完成後才有穩定環境測試每日事件縮放、倖存者負擔與長期威脅曲線。
