## 3. 玩家畫面規格

### 常駐與詳情

- 上中以大型數字顯示當前士氣，Stage 持續可見；左上保留小型三層金字塔。
- Stage 使用顏色與完整／裂痕／破碎形狀，不只靠顏色。
- 懸停延遲展開詳情；右鍵立即固定；外部點擊或再次右鍵關閉，關閉點擊不得穿透。
- 詳情包含目前值、上限、永久失去上限、下一條尚未跨越的門檻、方案名稱、目前效果與「回復士氣不會恢復階段」。Stage 2 顯示已無下一降階門檻，另提示歸零崩潰。
- 尚未初始化顯示未就緒，不以 0 假裝已崩潰；重開局清除上一局 UI 狀態。

### 分散式預測

- 輪初開始顯示；卡牌交易、資源、食物計畫、擊殺標記、殭屍資格、階段與下輪效果變更後更新。
- 食物區顯示消耗、剩餘、短缺與鼓舞餐點可執行狀態；資源區顯示已知階段扣除；戰鬥區顯示已安排支出與超量衰減；士氣區顯示已知變化與危險。
- 預測以目前狀態推算本輪末，不能假設玩家稍後會取得或使用任何卡牌；未知事件、未抽卡、隨機結果不納入。
- 殭屍生成後公開已確定的攻擊時點、士氣／永久上限損傷及下輪效果；尚未生成的威脅維持來源允許的模糊情報。
- 只有實際結束本輪且存在崩潰、跨階或永久上限損傷風險時顯示二次確認；一般 Turn 推進不冒充輪末。
- 取消確認不提交任何資料。確認前重新核對狀態版本；資料改變時刷新警告，避免提交過期預測。

### 預測揭露方案（使用者已確認）

GDD 要求預測與結算一致，HUD UX 同時禁止在士氣區集中加總殭屍永久上限損傷。建議採以下明確契約：

1. 規則層完整計算目前已知的上限損傷、士氣結果與危險旗標，UI 不另算。
2. 沒有已知永久上限損傷時，可顯示「依目前已知狀態：士氣 A → B」。
3. 存在永久上限損傷時，不在士氣區顯示可反推該總量的精確最終值，改顯示「存在永久損傷風險，查看殭屍詳情」，以及適用的跨階／崩潰警告。各隻殭屍仍顯示自身已知數值。
4. 不顯示刻意忽略永久損傷後的錯誤最終值；不把有限情報預測標成保證結果。
5. 正式結算報告完整顯示已發生的結果與來源。預測一致性在相同輸入且沒有新增未知結果時驗證；未知結果造成差異時可由報告追溯。

使用者已確認本方案；尚未同步 GDD／UX，後續需對齊其預測用語，不需重複請求此項範圍確認。

### 警告呈現規格（使用者已確認）

採「短文字說清楚、圖示方便掃視、特效提醒變化」。延續末日勤務手冊的紙條、筆記與有限功能色風格。所有會影響決策的警告必須有文字，不單獨依賴顏色或動畫。

| 情境 | 常駐短文案 | 圖像輔助 |
|---|---|---|
| 食物不足 | 糧食不夠／本輪預計短缺 {數量} | 食物缺口圖示與警告外框 |
| 鼓舞餐點不可支付 | 這輪無法加餐／可用食物不足 | 餐點圖示加斜線 |
| 預計跨階 | 士氣恐將跌入「{階段名稱}」／跨過後，本局無法恢復此階段 | 裂痕金字塔 |
| 永久上限損傷 | 有殭屍將造成永久創傷／查看殭屍了解詳情 | 破損上限圖示，不顯示傷害總量 |
| 預計崩潰 | 基地恐將撐不下去／依目前狀態，本輪結算後士氣將歸零 | 破碎金字塔與較強外框 |

- 文案只在對應條件成立時顯示；加餐失敗原因須使用實際原因，不將所有失敗一律寫成食物不足。
- 危險首次出現時圖示與外框短暫亮起一次，之後靜態保留；連續刷新不重播。危險解除後撤除。
- 懸停／右鍵詳情列出需求、可供應量、短缺、預計損失及來源。使用「本輪」「依目前已知狀態」標示預測性質；操作建議只在確定適用時顯示。
- 結束本輪的危險確認採紙張式警告框，標題「仍要結束本輪嗎？」；按鈕「返回處理」「仍然結束本輪」，預設焦點為返回處理。
- 多種危險合併於同一確認框，崩潰優先，其次跨階與永久損傷，不連續彈窗。取消及關閉不得穿透到遊戲操作。
- 正式跨階才使用中央金字塔放大、破損、效果移除／啟用與回縮演出；摘要持續可查。略過或減少動態效果仍保留完整結果與文字。
- 本次視覺素材範圍為警告小圖示、金字塔狀態、紙條與外框；不為每種危險新增大型插圖。
- 補充 E-07／E-09／E-11／E-14 驗收：灰階仍可辨識；連續刷新不反覆閃動；多危險只有一個確認框；減少動態效果與略過不漏摘要。

## 4. 資料與流程邊界

建議資料流：權威 Runtime 狀態 → 唯讀快照 → 共用計算 → 預測結果 → HUD；實際提交後則由完整交易結果 → 呈現佇列 → 下一個合法流程。

- 資產保存門檻、效果與顯示配置；本局採 Runtime 鎖定的 Profile 快照。
- 規則層負責計算及提交；UI 只能發送請求，不能支付資源、修改士氣或重播效果。
- 預測 API 不得呼叫實際 Resolve、暫時扣款再還原、排程效果、推進階段或消耗亂數。
- 優先抽取純計算共用點，不複製整套結算公式；保持既有結算順序與數值。
- 每個完成的交易提供來源、前後值、階段、實際效果替換與失敗原因；不得只從最終全域數值倒推。
- 卡牌與事件的崩潰報告也必須接到完整交易；輪末報告不是所有失敗的唯一來源。
- Failed 立即阻止遊戲操作及後續遊戲邏輯；視覺呈現可等待完整原因就緒，但不能因此延後失敗守衛。
- 呈現完成訊號只能放行一次；UI 關閉、略過或重開局不得重複進事件／下一輪。缺少呈現元件時需有可控的即時完成路徑，不能卡死測試或非正式場景。
- 不以全域 Time.timeScale 停止遊戲來取代流程鎖定。具體元件名稱與介面在實作前架構檢查後定案。

## 5. 三個實作切片與順序

### E1：資訊與預警

1. 補正式需求對照及針對性架構決策：預測／提交共用計算、完整交易結果、呈現與流程交接。
2. 盤點現有食物、戰鬥、保留量、效果資格與結算順序，建立唯讀快照及共用計算。
3. 接常駐士氣、金字塔、詳情與殭屍後果資訊。
4. 接分散預測與危險確認，處理資料刷新及過期確認。

交付：玩家能看到目前狀態、理解已知風險，且預覽不改變遊戲。

### E2：結算、跨階與崩潰

依序呈現其他資源變化 → 士氣計數 → 必要的金字塔跨階演出 → 崩潰畫面或合法事件／後續流程。

- 跨階時中央金字塔放大、舊層永久破損、列出「已移除／已添加」與「本局不可恢復」，最後回縮並留下摘要。
- 一次跨兩階時兩層均破損，只描述實際舊效果移除及最終新效果啟用，不假裝中間階段曾運作。
- 士氣回升只更新數字，不修復階層。
- 左鍵／Space 略過目前視覺步驟並補齊正確結果；輸入消耗後才交接事件，不能穿透。
- 減少動態效果以短暫淡入／切換替代位移與縮放，保留原因與不可逆資訊。
- 崩潰畫面列交易前後士氣、上限、最後來源及主要原因，以社群瓦解／放棄基地語意呈現。
- 最小結果操作提案：重新開始回到方案選擇；離開本局的出口依現有場景導覽確認，不憑空加入不存在的主選單。完整跨局歷史統計不在範圍內。

交付：結果可追溯、演出可略過，失敗後不能再操作或推進。

### E3：局前入口與整合

- 先提供既有「標準生存」完整 Profile 卡，展示三階效果與不可逆說明；只有一組也保留確認開始操作。
- 選擇完成後才初始化可操作 Run；不提供單項效果混搭或局中更換。
- 無效／遺漏 Profile 阻止開始並顯示原因；取消入口不建立半套 Run。
- 重開局清除舊通知、確認視窗、呈現佇列、訂閱與效果，重新鎖定 Profile。
- 在驗證場景確認後，以精準引用／冪等 Editor 工具整合 SampleScene；保留手動排版，不重建整個場景。

交付：完整開局 → 預警 → 結算 → 跨階／失敗 → 重開局流程。

## 2026-10-29：明確交易上下文與共用數值動畫（使用者確認）

採用明確交易上下文方案，不以呼叫者身分、同一幀或時間間隔猜測交易邊界。接口與類別名稱仍為規劃，未實作。

- 一次完整出牌、事件選項或輪末由外部權威流程建立交易上下文；該操作的各次資源修改傳遞同一上下文。相同卡牌下一次打出是不同交易。
- 共用數值介面可提供讀取、Set、Change 與變更通知；各系統保留付款、保留量、士氣批次等專用規則。共用介面不代表所有變更必須採同一修改邏輯。
- StateChanged 保留於底層變更通知，不作為本次共用資源數字／增減動畫的觸發入口。需要逐筆追溯的變更結果應包含交易識別、數值識別、來源、前後值與實際變化；成就及統計本體不納入 E2。
- TransactionCompleted 由外部交易擁有者在完整操作結束後發布一次，包含逐項變更與前後快照／實際淨變化，交給資源 UI。Change 不自行宣告整筆交易完成。
- UI 初次綁定、重設或重新開啟直接同步目前快照，不假裝取得資源。卡牌、事件與輪末共用同一資源動畫接口，輪末協調器只安排播放節奏、略過與單次交接。
- 例：支付 2 食物並取得 2 食物，底層保留兩次有效變更，完整結果淨變化 0，UI 不播放淨增減動畫；兩者仍由同一交易識別串起。
