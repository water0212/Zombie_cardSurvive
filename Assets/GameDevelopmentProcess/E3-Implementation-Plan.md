# PB-P0-014E3 實作計畫與工作對話交接

日期：2026-11-02。使用者要求規劃後建立新工作對話「PB-P0-014E3之規劃與實作」並交接實作。本文件是 E3 內部步驟，不新增另一套 PB 排程；唯一主線仍為 Story-Sequence.md，驗收以 E3 四份 Story 與 Design/Run-Lifecycle.md 為準。

## 已確認的場景分工

1. 士氣崩潰畫面在 SampleScene（主遊戲）。
2. 切回另一個主選單 Scene，先以白畫面占位。
3. 在主選單階段完成舊局資料清理；完成前不能開始新局。
4. 在該主選單 Scene 的介面選士氣 Profile／已支援設定。
5. 重新載入 SampleScene，建立並進入新遊戲。

白畫面本身就是未來主畫面的占位 Scene，不是在 SampleScene 上顯示白色面板。離場前可先使舊局失效、停止回呼與卸載，但主選單 Ready 必須代表清理確已完成。Stage 已確認指士氣 Profile，新局從崩潰 Stage 0 開始。

## 實作順序

### 第一段：程式現況與所有權盤點

- 讀取 README、Story-Sequence、E3-001～004、Run-Lifecycle、Technical-Debt、E2 API 及相關現行腳本。
- 盤點 RunPhaseController.StartRun／StartRunCore、startRunOnAwake、OnDestroy，以及各 System／控制器初始化與釋放能力。尤其確認銷毀流程是否有重設 Profile、推進事件或釋放鎖的副作用。
- 製作單局清理對照：資料持有者、清理方法、Scene／static／常駐範圍、舊回呼與訂閱風險。不要假定 reload Scene 已完整 Reset。
- 檢查使用者未提交修改，保留能量立即更新、InTurnfadeDuration 與 Update Style；先備份必要檔案，不 reset Git 或覆蓋手動排版。
- 保留 E2 未驗收界線，不把 E3 的開工或本次計畫標成 E2 全部 Done。

### 第二段：流程部件與占位入口（E3-001／002）

- 確定一個跨 Scene 的流程所有者，管理 MenuReady／轉場／初始化／Gameplay／返回清理等生命週期與單次請求；具體型別名稱由盤點決定，不任意增加多層框架。
- 定義開局設定／結果及可供未來正式 UI 呼叫的入口。先只實作有效 Profile 與必要識別，其他設定保留擴充邊界，不新增玩法。
- 以必要最小的跨 Scene 存續機制傳遞已驗證快照，舊 Run 與 UI 不常駐複製；避免重複管理器與事件訂閱。
- 建立獨立主選單 Scene（建議 MainMenu），只有白背景、Profile 選擇、開始與狀態／錯誤提示。正式 UI 由 PB-P3-005 處理。
- 主選單確認後載入 SampleScene，由既有 RunPhaseController 初始化一次。先驗證再修改，明確處理自動 Awake 開局，防止雙啟動。
- 對取消、缺 Profile、Scene 引用不合法、載入／初始化失敗提供可回入口重試的結果，不留下可操作半局。

### 第三段：崩潰返回與整局清理（E3-003）

- 訂閱 CollapseReportView.RestartRequested，單次返回主選單；必要時共用合法離局入口。UI 不直接清空各 System。
- 離場前使舊局及其回呼識別失效；停用／卸載不應自動把舊 Run 放行到下一事件。
- 依所有權清理卡牌、倉庫、保留、建築工作、探索、事件與旗標、資源、已存在人口、士氣／Profile／能量修正／下輪效果，以及通知、確認、動畫、操作鎖與訂閱。
- 主選單入口清理完成後才 Ready。不要刪除資料 Asset、玩家手動場景排版、存檔或歷史紀錄來代替清理。
- 新局只從確認設定後的初始化建立初始值；不以重新啟用舊 Run 冒充新局。

### 第四段：跨場景驗收與交付（E3-004）

- 定向測試：無效設定、確認／返回去重、清理前禁止開始、初始化一次、舊回呼失效、快照固定與失敗可重試。
- 實際 Scene 驗證：崩潰 → 主選單白畫面 → 清局完成 → 選 Profile → SampleScene 新局；連續重開至少兩次，檢查舊效果、訂閱、管理物件與操作鎖不累積。
- 新局可以正常打牌、事件、探索與輪末；士氣 100/100、Stage 0，舊 Stage 1 資源效果及 Stage 2 能量修正不殘留。
- 檢查跨畫面輸入不穿透。正式主選單美術／完整卡片／視覺矩陣不阻擋 E3；E2 原有視覺與輸入驗收仍如實保留。
- 先在測試副本／精準接線工具驗證再整合，保留 SampleScene 原 GUID 與實際控制器，不重建整場景、不手寫整份 Unity YAML。
- 更新 Story 狀態與證據、開發日誌，交付 ScriptCodeReview/E3_API_Review.md，包含 API、場景／腳本圖、清理對照、問題、未測項與後續擴充。
