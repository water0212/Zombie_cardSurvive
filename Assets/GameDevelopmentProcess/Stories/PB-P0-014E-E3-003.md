# PB-P0-014E-E3-003：崩潰後返回主選單並清除整局資料

- 狀態：Planned，尚未實作／驗收。
- 範圍修訂：2026-11-02。
- 前置：PB-P0-014E-E3-002、PB-P0-014E-E2-003。
- 流程規格：[Run Lifecycle](../Design/Run-Lifecycle.md)；順序：[Story-Sequence](../Story-Sequence.md)。

## 範圍

接收 CollapseReportView.RestartRequested，交由 E3 流程部件處理，而非報告 UI 自行重設或直接 StartRun。從遊戲內 SampleScene 切回白畫面主選單 Scene，結束舊局並清除其所有單局狀態；完成清理後才允許重新選擇 Profile／設定與要求新局。

可在離場前及主選單載入後分段清理，但只有清理完成才視為 Ready；不能只換白畫面就宣稱整局已清空。舊世代先失效，任何卸載、停用、事件或協程回呼不得趁交接推進舊事件或新局。Scene 卸載不是 static Systems、事件訂閱與跨場景物件的自動重設保證。

## 驗收條件

- [ ] 士氣崩潰報告的重新開始只提出一次返回主選單要求，實際 Scene 從 SampleScene 切回占位主選單。
- [ ] 返回時結束舊 Run，清除／釋放原單局牌組與倉庫實例、建築／施工／製作／保留、探索地區／卡包、事件／旗標、資源與人口等已有狀態；完整清單以實作盤點為準。
- [ ] 清除士氣目前值／上限／Stage 的舊局持有狀態、Profile／待生效能量修正與下輪效果；不依卸載自動完成。新局初始值由 E3-002 統一建立。
- [ ] 清除舊動畫佇列、報告、預警／確認、替換／探索等臨時 UI 狀態與舊操作鎖；清理中仍不允許開始。
- [ ] 舊交易／協程／事件回呼在轉場及新局後無法寫入或重複進流程；跨場景管理物件與訂閱不累積。
- [ ] 不修改共用 ScriptableObject 定義、玩家原始場景排版，也不刪除歷史紀錄／既有存檔以冒充單局清理。
- [ ] 返回占位主選單後可重新選 Profile，再開新局，不直接沿用舊局或未確認的上次選擇。
- [ ] 若 CollapseReportView 的離開本局要求接到同一返回入口，也走同一清理流程；未接線前維持隱藏，不新增無效按鈕。

## 不在範圍與證據

正式主選單／結果美術、存檔刪除與讀檔不在範圍。尚無新證據；需實際跨 Scene 與重複重開測試，不能只單獨呼叫 Reset 就當整合通過。
